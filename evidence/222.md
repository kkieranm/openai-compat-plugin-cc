# OAI-222 — evidence

A 7-stage, Codex-designed exhaustive sampling-parameter search (`--temperature`, `--top_p`,
`--top_k`, `--min_p`, `reasoning_effort`, `--structured-output`, `--parallel`) run over two finalist
models — `qwen/qwen3.8-27b` and `qwen/qwen3.5-9b`, both `enable_thinking: false` per OAI-221 — across
~150 model invocations, 2026-08-26/27. Every parameter was injected via a scratchpad HTTP proxy
(neither the plugin nor `bench/run.mjs` can send these fields — see OAI-214/OAI-215), verified before
each run by reading the proxy's own `/inject` echo and by asserting `reasoning_tokens=0` on a probe
call. Full stage-by-stage numbers, including two rounds of Codex review of the findings and the
required corrections, are in the session record; this file states only what survived.

## Method

- Stage 2: N=2–3 canonical baseline per model, no sampling injection, full `bench/` corpus.
- Stage 3: mechanism tests (`--structured-output` on/off, `reasoning_effort` low/medium/xhigh).
- Stage 4: 8-point space-filling sampling design, N=1 screen, 3-case panel
  (`config-origin`, `hold4-unref-order`, `docs-only`).
- Stage 5: N=3 confirmation of the 8 standout points from Stage 4.
- Stage 6: N=5 confirmation of the frozen per-model config against the full original 6-case corpus,
  compared against Stage 2's baseline.
- Stage 7: N=5 confirmation against two hold-out cases (`hold1-exit-code`, `hold2-hostile-coercion`)
  that were never part of any search panel and were built during this same investigation
  (see OAI-221's evidence for corpus provenance).

`hold4-unref-order` doesn't count as a holdout for Stage 7 — it was in the Stage 4/5 search panel.

## Result

Sampling-parameter tuning bought a real precision gain and no generalizable recall gain.

- **Precision**: `qwen/qwen3.5-9b`'s clean-code control (`docs-only`) went from 2/3 clean at
  baseline to 5/5 clean under its frozen config (point 7: temp=0.15, top_p=0.9, top_k=25,
  min_p=0.025), held through both Stage 6 and Stage 7.
- **Recall regression**: the same config's recall on the three hardest full-corpus cases
  (`model-info`, `scaffold`, `structured`) fell from 1/3 anchored each at baseline (3 of 9 runs) to
  0 anchored in every rep that produced an answer under tuning (0 of 11 answered runs), with 4
  additional timeouts tuning didn't have at baseline. The config was selected on a 2-case panel that
  never included these three cases — the pattern Codex's tune/hold-out design was built to catch,
  observed directly. Codex's own review: "consistent enough to call an observed regression plainly,
  while the small samples prevent a confident causal or population-level claim."
- **No effect on `qwen/qwen3.8-27b`'s two full-corpus timeouts** (`model-info`, `scaffold`) — 0/5
  reps completed in either the untuned or tuned arm. See OAI-223 for the capacity-ceiling finding
  behind this.
- **Zero hold-out recall**: on `hold1-exit-code` (4 real defects) and `hold2-hostile-coercion` (1
  real defect), both finalists' frozen configs anchored **zero defects across 20 combined
  repetitions** (N=5 x 2 cases x 2 models). 6 of those 20 were parser failures or a timeout rather
  than semantic misses (see OAI-224), so this is not 20 independent recall observations — Codex's
  qualifier, applied after an initial draft of this finding was flagged as overstated.

## Conclusion

`enable_thinking: false` (OAI-221) is the only effective lever among those tested. Sampling search,
pursued exhaustively, did not make either finalist capable of the review-ladder task outside the
narrow defect shape (`config-origin`'s missing-validation pattern) its config happened to be tuned
against. This does not support adding a local-model review-ladder stage on recall grounds yet.

**Reopening path** (Codex): fix the OAI-212/OAI-224 parser gap first, since it accounted for half of
the qwen3.8 hold-out failures; then test materially different models — not merely larger ones —
against a preregistered, structurally diverse corpus with explicit recall and runtime gates; reopen
integration only if a candidate shows repeatable recall across multiple independent defect families,
not just the one shape tested here. A group-A advisory-only shadow deployment could still run as a
non-gating experiment, but nothing in this data set gives it a positive recall rationale over simply
not adding the stage yet.

**Caveat on the holdouts**: `hold1-exit-code` and `hold2-hostile-coercion` were built during this
same investigation from this repository's own commit history. They were never used by the search,
so the 0/20 hold-out result stands, but they are few in number and their defect shapes were chosen
by the same investigator running the search — this bounds how far the zero-recall result
generalizes beyond this benchmark.
