Direct API probes, 2026-09-01, of the two servers installed on this machine — the "second server"
OAI-13's items (1) and (2) waited on since 2026-07-28. Every row is one literal request and the
verbatim body the server returned; the account of what the plugin does with the LM Studio error
frame is read from the code and confirmed by the real-CLI reproduction below. The probe scripts are reproduced at the
end of this file; a run was `node probe.mjs out.json` from a directory with the script, with the
omlx key read from `~/.omlx/settings.json` and LM Studio unauthenticated.

## What (1) and (2) needed, and what was found

- **(1)** a 400/422 whose body names `response_format` past the 400-character cap `assertOk` keeps on
  `.responseBody`. **Not observed.** The longest refusal naming `response_format` was 280 bytes (oMLX);
  LM Studio's are 53–66 bytes. Neither grows with the request: the same refusal with a 2,000-character
  message body was byte-identical (`bad_temp_long_messages`).
- **(2)** a 400/422 that echoes the request JSON, so a refusal of some other field carries the words
  `response_format`/`stream`/`stream_options`. **Not observed.** oMLX's pydantic wrapper flattens to
  `body -> <field>: <message>` and names the refused field structurally in `error.param`; LM Studio
  names its own config key (`llm.prediction.temperature`). Neither body contains the request.
- oMLX refused no object-shaped `response_format` — `{type:'bogus'}`, a missing `json_schema`, a
  non-object `schema` all return 200 and are silently ignored; only a non-object `response_format`
  value (a string, a number) is a 422, named structurally in `error.param`. LM Studio refuses each of those with a 400 whose body names the field, pre-stream,
  `stream: true` or not.
- oMLX carries the OpenAI error envelope (`{error:{message,type,param,code}}`) with `param` set on
  every validation refusal; LM Studio's is `{error:"<prose>"}` — no `type`, `param` or `code` — except
  `reasoning_effort`, which uses the envelope. A shape-not-name read is possible on one server and
  not the other.

## The finding this probe DID produce: LM Studio streams a refusal as HTTP 200

With `stream: true` — the plugin's default — LM Studio delivers a **sampling-parameter or
context-overflow refusal as an HTTP 200 `text/event-stream` whose only event is `event: error`**,
carrying `data: {"error":{"message":…},"message":…}` and no `[DONE]`. `scripts/lib/sse.mjs` drops
`event:` lines by design and hands the data frame to `applyFrame`, which finds no `choices` — so
`refuseUnusable` classifies it `empty-completion`, a RETRYABLE shape, and the run re-sends a request
that will refuse identically. Reproduced through the real CLI (below). The pre-stream 400s above are
unaffected: `response_format` refusals still arrive as 400 before any stream opens.

Reachable from the CLI today via **context overflow**: `context-guard.mjs` estimates 3.4 chars/token,
and CJK text tokenizes near 1 char/token, so a 200,308-character prompt is estimated at ~58,897
tokens (passes a 154,624 window) and overflows the server. Every sampling value LM Studio refused
(`max_tokens < 1`, `temperature < 0`, `top_p > 1`, `min_p > 1`) is also refused client-side by
`parseNumber`, so those are not reachable from the CLI; `temperature: 3`, `top_k: 0`, `top_k: -1`,
`presence_penalty: 5` were accepted by the server.

### `probe.mjs`

```js
import { readFileSync, writeFileSync } from 'node:fs';
const key = JSON.parse(readFileSync(process.env.HOME + '/.omlx/settings.json', 'utf8')).auth.api_key;
const servers = {
  omlx: { url: 'http://localhost:8000/v1', headers: { Authorization: `Bearer ${key}` }, model: process.env.OMLX_MODEL },
  lmstudio: { url: 'http://localhost:1234/v1', headers: {}, model: process.env.LMS_MODEL },
};
const msgs = [{ role: 'user', content: 'Say hi.' }];
const longMsgs = [{ role: 'user', content: 'x'.repeat(2000) + ' Say hi.' }];
const schema = { type: 'object', properties: { hi: { type: 'string' } }, required: ['hi'], additionalProperties: false };
const rf = { type: 'json_schema', json_schema: { name: 'hi', strict: true, schema } };
const cases = {
  bogus_rf_type: { response_format: { type: 'bogus' } },
  valid_json_schema: { response_format: rf },
  bad_temp_with_rf_stream: { temperature: 'hot', response_format: rf, stream: true, stream_options: { include_usage: true } },
  bad_temp_long_messages: { temperature: 'hot', response_format: rf, stream: true, stream_options: { include_usage: true }, messages: longMsgs },
  unknown_key: { frobnicate: 1 },
  unknown_model: { model: 'no-such-model' },
  stream_options_without_stream: { stream: false, stream_options: { include_usage: true } },
  negative_max_tokens: { max_tokens: -5 },
  huge_max_tokens: { max_tokens: 99999999 },
  invalid_schema_value: { response_format: { type: 'json_schema', json_schema: { name: 'hi', schema: 'nope' } } },
  rf_missing_json_schema: { response_format: { type: 'json_schema' } },
};
const out = {};
for (const [sname, s] of Object.entries(servers)) {
  if (!s.model) continue;
  out[sname] = {};
  for (const [cname, patch] of Object.entries(cases)) {
    const body = { model: s.model, messages: msgs, max_tokens: 8, stream: false, ...patch };
    const t0 = Date.now();
    let rec;
    try {
      const r = await fetch(`${s.url}/chat/completions`, { method: 'POST', headers: { 'content-type': 'application/json', ...s.headers }, body: JSON.stringify(body), signal: AbortSignal.timeout(180000) });
      const text = await r.text();
      rec = { status: r.status, statusText: r.statusText, contentType: r.headers.get('content-type'), bodyLength: text.length, body: text.slice(0, 3000), ms: Date.now() - t0 };
    } catch (e) { rec = { threw: String(e), ms: Date.now() - t0 }; }
    out[sname][cname] = rec;
    console.log(`${sname} ${cname}: ${rec.status ?? rec.threw} len=${rec.bodyLength ?? '-'} ${rec.ms}ms`);
  }
}
writeFileSync(process.argv[2], JSON.stringify(out, null, 2));
```

import { readFileSync, writeFileSync } from 'node:fs';
const key = JSON.parse(readFileSync(process.env.HOME + '/.omlx/settings.json', 'utf8')).auth.api_key;
// CJK text tokenizes near one token per char, so a modest char count overflows a window the client's 3.4 chars/token estimate would pass.
const cjk = (n) => { let s = ''; const base = 0x4e00; for (let i = 0; i < n; i++) s += String.fromCharCode(base + (i * 7919) % 20000); return s; };
const servers = {
  omlx: { url: 'http://localhost:8000/v1', headers: { Authorization: `Bearer ${key}` }, model: 'mlx-community--Qwen3-14B-4bit', chars: 60000 },
  lmstudio: { url: 'http://localhost:1234/v1', headers: {}, model: 'qwen/qwen3.5-9b', chars: 200000 },
};
const out = {};
for (const [sname, s] of Object.entries(servers)) {
  const body = { model: s.model, messages: [{ role: 'user', content: cjk(s.chars) + '\nSay hi.' }], max_tokens: 8, stream: true, stream_options: { include_usage: true } };
  const t0 = Date.now();
  let rec;
  try {
    const r = await fetch(`${s.url}/chat/completions`, { method: 'POST', headers: { 'content-type': 'application/json', ...s.headers }, body: JSON.stringify(body), signal: AbortSignal.timeout(500000) });
    const text = await r.text();
    rec = { status: r.status, contentType: r.headers.get('content-type'), bodyLength: text.length, head: text.slice(0, 900), tail: text.slice(-300), ms: Date.now() - t0 };
  } catch (e) { rec = { threw: String(e), ms: Date.now() - t0 }; }
  out[sname] = rec;
  console.log(`=== ${sname} overflow(${s.chars} CJK chars) → ${rec.status ?? rec.threw} ct=${rec.contentType} len=${rec.bodyLength} ${rec.ms}ms\n${rec.head ?? ''}\n...\n${rec.tail ?? ''}`);
}
writeFileSync(process.argv[2], JSON.stringify(out, null, 2));
